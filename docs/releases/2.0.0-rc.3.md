# SDK 2.0.0-rc.3 tester-beta consolidation

Prepared 2026-10-08. The private root and all eight canonical package manifests
are now `2.0.0-rc.3`, versioned with the existing Changesets RC workflow and
packed locally. No publication, stable promotion, deployment, production reset,
or security-epoch activation was performed. Tester-beta is the rollout audience,
not a new npm `beta` tag.

## Validation commands and parent handoff

Versioning is already applied. Do not run `version-packages` again for this
candidate. The private root, which Changesets does not bump, was aligned
explicitly to rc.3. Reproduce the release checks from the parent-selected commit:

```bash
mkdir -p artifacts
pnpm install --frozen-lockfile
pnpm release:check
pnpm contracts:generate
pnpm typecheck
pnpm test
pnpm build
pnpm api:report
pnpm pack:dry
pnpm publint
pnpm attw
pnpm docs:build
```

Review all generated version/changelog/Changesets changes and generated API/docs drift.
Run the tests with an isolated PostgreSQL 17 `unet_security_test` database using
`UNET_SECURITY_TEST_POSTGRES_URL`, without printing its value; absent database
configuration skips the real database cases and is not release acceptance.

In a disposable consumer install only required packages and their matching
canonical transitive dependencies from the exact eight rc.3 tarballs in one
package-manager transaction, or use consumer-local overrides. Place only
`scripts/packed-release-smoke.mjs` in that consumer and run
`node packed-release-smoke.mjs` there so package resolution uses its installation,
not the SDK checkout's dependencies. Never install issuer/setup into a browser app.
Record the manifest hashes and test receipt; old rc.2 receipts do not cover rc.3.

Before any separately authorized tag operation, validate the expected CI tag:

```powershell
$env:GITHUB_REF_NAME = 'sdk-v2.0.0-rc.3'
pnpm release:check
Remove-Item Env:GITHUB_REF_NAME
```

Tagged-release checks reject version mismatch, unsupported prerelease suffixes,
unapplied Changesets, missing/wrong RC mode, and stable versions while prerelease
mode is active. Untagged checks permit preparation with pending Changesets.
This guard is not a substitute for comparing candidate artifacts with npm.

## CI and remaining gates

The existing release workflow runs on `sdk-v*` tags. RC tags select the protected
`npm-prerelease` environment and npm `next`, not `latest`. It uses Node 22,
pnpm 10.33.0, npm 11.16.0, PostgreSQL 17, frozen installation, release checks,
tests/build/docs, strict API reports, generated-file drift detection, tarball
checksums, publint and attw before publishing the exact tarballs with provenance.
Ordinary CI checks Node 20 and 22. Environment authorization and git operations
belong to the parent; this preparation does not perform them.

Release blockers:

- Parent selects the consolidated commit for PR/OIDC. The selected SQL test,
  versioned metadata and archived Changesets are part of this candidate.
- Pass the committed-source Node 20/22 matrix, real PostgreSQL tests, clean
  frozen installation and fresh consumer installation. Local Node 24 artifacts
  and component smoke do not substitute for that matrix.
- Verify maintained providers' installed/bundled candidate, browser-bound login,
  header-only delivery, V2 callbacks with durable nonce stores, authenticated
  hash-only admission, recovery/publication transaction hooks and issuer-wide
  coordination. Component receipts do not certify the completed rollout.
- Parent-owned full wallet/device and deployed-service acceptance, legacy
  session/capability cutover, and production/security activation remain separate
  gates. This SDK work does not close them or approve stable promotion.
- Publication and tagging remain separately controlled. Do not publish rc.2
  again, use a stable tag, rewrite old tags, or treat `@next` as the new candidate.
