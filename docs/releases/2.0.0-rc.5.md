# SDK 2.0.0-rc.5 manual verification candidate

Prepared October 13, 2026. This is a local, unpublished fixed-version candidate,
not stable promotion, deployed acceptance, or authorization to publish.

## Release scope

The Changesets CLI applied the patch changeset for `@u-net/client`,
`@u-net/contracts`, and `@u-net/verification`. The fixed group advances all eight
canonical packages to `2.0.0-rc.5`; the private root is aligned explicitly.
The applied record is `.changeset/pre/manual-verification-v2.md`.
RC mode remains enabled. Do not run versioning again for this candidate.
Compatibility forwarders and private examples are not promoted or published.

The candidate adds public V2 challenges, header-only private polling authority,
native predicate/expiry submissions, and origin/request-bound historical receipts.
Typed retryable 503 statuses are fully validated and session-bound; they are not
success, revocation, or permission to retry without consent. Trust error codes,
eight-check limits, reference/capability/proof bounds, ordered check digests,
nonce/timestamp requirements, and terminal outcome consistency are synchronized.
See [the manual verification guide](/guides/manual-verification-v2).

## Evidence and required gates

Local SDK checks use Node 24, not the required clean Node 20/22 release matrix.
The corrected focused run passed 91 tests across client transport,
legacy HTTP regression, and signed historical receipts. It includes strict 503,
error-code, request/proof boundary, and noncanonical receipt cases.
No local component test substitutes for PostgreSQL, real Android proof generation,
Ledger V2 lifecycle evidence, or physical-phone acceptance.

The selected-source packaging checks subsequently passed on Node 24.19.0:

- The existing clean workspace build passed for canonical packages, compatibility
  forwarders, and typed examples; all eight rc.5 artifacts were packed.
- API Extractor passed across all eight packages. TypeDoc and the manual
  verification guide's TypeScript sample passed.
- Publint passed for all eight packages. Are The Types Wrong passed using the
  repository's `esm-only` profile; CommonJS remains intentionally unsupported.
- Packed artifacts have matching versions and internal `^2.0.0-rc.5` ranges,
  permitted file inventories, and recorded SHA-256/SHA-512 integrities.
- A fresh isolated pnpm 10.33.0 consumer installed the exact eight local
  tarballs, with consumer-local overrides for unpublished internal versions.
  External dependencies were installed from public npm/cache, with lifecycle
  scripts disabled. The expanded smoke passed all eight imports, V2 challenge,
  submission, typed unavailable recovery, private polling, receipt verification
  and tamper/revocation rejection, plus browser-bound login replay checks.
- A bounded documentation snapshot built successfully from tracked docs plus
  the selected release overlays and complete generated API documentation.
  Dirty privacy notes and private experiments were excluded. Nonfatal bundle-size
  warnings remain; no documentation deployment occurred.

The initial sandbox symlink attempt and offline dependency-resolution attempts
failed. A permitted unsandboxed installation with public dependency resolution
passed afterward; those initial attempts are not counted as successful gates.
The smoke uses synthetic proof transport, not real proof or database verification.
No `UNET_SECURITY_TEST_POSTGRES_URL` was configured for local acceptance.

## Publication boundary

The release workflow runs only after an explicitly approved `sdk-v2.0.0-rc.5`
tag. It uses the protected `npm-prerelease` environment, Node 22, PostgreSQL 17,
pnpm 10.33.0, npm 11.16.0, Trusted Publishing/OIDC, provenance, generated-file
drift checks, package checksums, publint, and Are The Types Wrong.
It publishes all eight exact tarballs to `next`, never `latest`, and attaches
artifacts/manifests/checksums to the matching prerelease.
Verify registry availability before publication; do not reuse an existing npm
version or overwrite an old tag. Git operations, publication, deployment,
maintained-provider migration, and Android acceptance remain parent-owned gates.
